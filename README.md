# DogTrial — native app (Capacitor)

This wraps the existing DogTrial web app (the 30-day dog simulator) as a real
iOS and Android app using [Capacitor](https://capacitorjs.com/), so almost
all of the existing HTML/CSS/JS is reused as-is.

## Why builds happen in the cloud, not on this Mac

This machine (MacBook9,1, 2016, Core m5) is stuck on macOS 12.6.8 — Apple
doesn't support any newer macOS on this model, and the newest Xcode that
runs on macOS 12 is far too old to submit to the App Store today. So the
actual iOS/Android compiling happens on **Codemagic**, a cloud CI service
with real Mac + Xcode + Android SDK build machines. This Mac only edits
code and pushes it to GitHub; Codemagic does the rest.

## Project layout

- `www/` — the web app itself (`index.html`), copied from the DogTrial
  simulator. To update it, replace this file with the latest version and
  run `npx cap sync`.
- `ios/` — native iOS project shell (generated by Capacitor).
- `android/` — native Android project shell (generated by Capacitor).
- `capacitor.config.json` — app id (`dog.dogtrial.app`), name, colors.
- `codemagic.yaml` — the cloud build pipeline (iOS + Android workflows).

## What's left to do (needs your accounts — I can't create these for you)

1. **GitHub** — code needs to live in a repo so Codemagic can pull it.
2. **Apple Developer Program** ($99/year) — apple.com/developer — required
   to sign and submit an iOS build to TestFlight/App Store.
3. **Google Play Console** ($25 one-time) — play.google.com/console —
   required to publish an Android build.
4. **Codemagic account** (free tier covers this) — codemagic.io — connect
   your GitHub repo, then connect your Apple/Google credentials inside
   Codemagic's dashboard (Team settings → Code signing identities /
   Integrations). Codemagic then reads `codemagic.yaml` in this repo
   automatically and knows how to build both apps.

Once those four are in place, every push to the repo (or a manual trigger
in the Codemagic dashboard) builds a real `.ipa` and `.aab` and can upload
straight to TestFlight / Play internal testing — no local Xcode needed at
any point.
